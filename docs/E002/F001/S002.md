# S002 · Huecos, canónico local y aquas build

[Inicio](../../README.md) › [E002](../README.md) › [F001](README.md) › S002

`aquas build <carpeta>` arma el `CLAUDE.md` del hijo con la central sellada y los huecos que el hijo llena en `gobierno/canonico/huecos/`.

## En una frase

El hijo escribe solo lo suyo; lo demás llega final desde la central.

## Para qué existe

**El problema.** Tras install, el hijo tiene las reglas pero no un `CLAUDE.md` propio. Y si pudiera reescribir cualquier sección, la herencia no valdría nada.

**La solución.** La central marca qué secciones son huecos con `<!-- hueco: nombre -->` … `<!-- /hueco -->`. El hijo escribe `gobierno/canonico/huecos/<nombre>.md`. Build revisa el [sello](../../glosario.md#sello), reemplaza cada hueco y rechaza lo demás.

Contrato del [slice](../../glosario.md#slice):

| Campo | Valor |
|---|---|
| Objetivo | Armar el `CLAUDE.md` del hijo desde central + huecos |
| Incluye | `hijo.Build`, marcadores en la constitución (Misión y Mapa del repo), comando `aquas build` |
| Excluye | Agentes del hijo, secciones añadidas por el hijo, update (S003), report (S004) |
| Prueba | `go test ./internal/hijo/ -run TestBuildRellenaHuecosSinTocarFinal` |

## Analogía

Piensa en un **formulario oficial**.

- La oficina imprime el texto fijo y deja casillas en blanco.
- Tú llenas las casillas; no puedes tachar el texto impreso.

Límite de la analogía: aquí un programa rechaza el formulario si escribes fuera de las casillas.

## Diagrama

```mermaid
sequenceDiagram
    participant U as Usuario
    participant B as aquas build
    participant H as Carpeta del hijo
    U->>B: aquas build ./landing
    B->>H: ¿central igual al lock?
    H-->>B: sí
    B->>H: lee huecos locales
    B->>B: reemplaza cada hueco, rechaza nombres que no son hueco
    B->>H: escribe CLAUDE.md (GENERADO)
    B-->>U: CLAUDE.md armado
```

## Ejemplo de punta a punta

<a id="EJ-E002-F001-S002"></a>

continúa: [EJ-E002-F001](README.md#EJ-E002-F001)

1. Se instaló la central en una carpeta de `.tmp/` y se escribió solo `mision.md`.
2. Build falló: «hueco sin llenar: mapa».
3. Con `mapa.md` también, build armó el `CLAUDE.md` con la misión de la landing.
4. Con un `principios.md` extra, build falló: «no son huecos de la central (sección final, no se redefine): principios».

## Paso a paso

1. Comparar cada archivo sellado con su hash del lock.
2. Leer los huecos locales.
3. Reemplazar cada bloque hueco por su archivo local; si falta, fallar.
4. Si sobra un archivo local que no es hueco, fallar.
5. Escribir `CLAUDE.md` con la marca GENERADO.

## Cómo se usa

- Llenar `gobierno/canonico/huecos/mision.md` y `mapa.md` en el hijo.
- Correr `aquas build <carpeta-del-hijo>`.
